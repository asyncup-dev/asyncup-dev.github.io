Roles and permissions ​

RoleHow you get itWhat it grants
OperatorHolds the operator token (OPERATOR_TOKEN)Everything, including workspace settings, while token sign-in is on
Workspace adminA Google Workspace super or delegated admin (through the Directory), or in the SAML admin groupThe full console: every standup, workspace settings, deleting archived standups
Manager (standup admin)Ran setup, created the standup in the web app, or was granted admin @userConfigure that standup from Chat or the web app; manage the schedules and time-off requests of people on it
ParticipantOn the standup's roster: picked in the People grid, add @user, or a member of the Google Group it followsAnswer, edit, skip, DM self-service, their own page at /app/me
Everyone in the space—status, trends, blockers, blocker, polls, help, and setup

Notes:

  • A standup always keeps at least one admin; removing the last is refused.
  • A standup created with no admins (for example from a script with the operator token) is open to configuration by anyone in its space. Name an admin when creating on someone's behalf.
  • The web app and the JSON API share one authorisation model. MCP tools act as the token's owner and see exactly what that person sees (Claude Code and MCP).
  • Who may mark someone away is set per standup by its time-off policy.
